## Context key

- **Warm Stage:** authored product surface on the near-black canvas with graphite content surfaces and one warm-white primary action.
- **Immersive:** black/video-owned canvas with legible neutral over-video chrome and selective style-accent progress.
- **Native utility:** system-owned or recovery-oriented UI where adaptive platform treatment is more truthful and usable than forcing Quiet Stage.

## Audit decisions driving P1 implementation

1. Unify the entire authored onboarding shell on Warm Stage, add the approved pain beat, and preserve the existing single action/data paths.
2. Replace both placeholder gradient/fake-content onboarding mocks with checked-in 567 brand assets and authored product-language illustrations that do not impersonate user content.
3. Apply the selectable-row and primary-action primitives to onboarding, Style selection, and the import preview; keep native permission/picker/alert/rename/export/recovery UI native.
4. Remove decorative Feed gradient/glow treatments that conflict with the flat immersive rule, while keeping video-owned black framing and white over-video controls.
5. Tighten shared non-color semantics, Reduce Motion, modal progress, and Warm Stage child-row tokens where the matrix identifies concrete gaps.
6. P2—not P1—owns truthful paywall copy, transaction-state completeness, entitlement policy, caps, restore durability, and iCloud-claim removal. P1 supplies the canonical final visual shell without pre-empting G2.
